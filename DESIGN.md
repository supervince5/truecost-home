# TrueCost Home visual system

The interface supports a first-time buyer reviewing property evidence and planning repair cash. It is a working application, not a marketing-only landing page.

The October 25 redesign uses the user's reference palette exactly: sage #CCD5AE, pale sage #E9EDC8, cream #FEFAE1, warm cream #FAEDCD, and tan #D4A373. Dark olive #30372B and secondary olive #606650 provide readable contrast; the light swatches are surfaces, never low-contrast text.

Apple-inspired principles: locally hosted DM Sans body text and Lora editorial headings, generous spacing, progressive disclosure, consistent controls, immediate pressed feedback, functional translucent navigation, and restrained step transitions. Respect reduced motion, contrast, and transparency preferences. No invented statistics, fake listings, automatic eligibility claims, or decorative dashboards.

Use Tailwind v4 for layout utilities and theme tokens, with CSS for shared control states and responsive component behavior. The landing composition references Beside: a centered headline, narrow supporting copy, one primary action, generous vertical space, and a separate explanation section. Cream is an accent alongside near-white surfaces. The tool opens as a focused, photo-first single-column workspace. Budget is optional and collapsed; property details and inspection text use disclosures. Results retain a wider evidence area with a supporting budget panel, stacked on mobile.

The three steps remain Home & budget, Review & results, and Next steps. Live findings retain their submitted evidence snapshot. Repair scope confirmation remains separate from accepting an observation. Unknown values stay visible, and assistance does not enter baseline cash flow.

The home guide has seven keyboard-accessible tabs, a responsive house illustration, and transitions that follow the selected area. The welcome entrance and button feedback are restrained. Reduced-motion preferences disable these animations. Interface copy contains no em dashes. Analysis progress reflects actual view completion rather than an invented percentage.
